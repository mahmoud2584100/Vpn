# X4G — VLESS Gateway

این پروژه یک سرور Python/FastAPI برای **VLESS روی WebSocket و XHTTP** همراه با پنل مدیریتی فارسی و ربات اختیاری تلگرام است. برای استفاده، باید آن را روی یک سرور یا میزبان قابل‌دسترسی اجرا کنید؛ قرار دادن کد در GitHub به‌تنهایی VPN ایجاد نمی‌کند.

## نتیجه بررسی و محدودیت‌ها

نسخه اصلاح‌شده در تست محلی با **Xray 26.3.27** روی WebSocket و XHTTP packet-up انتقال داده موفق داشت. جزئیات در [REVIEW.md](REVIEW.md) است. هیچ تستی روی اینترنت داخل ایران انجام نشده و اتصال بدون قطعی تضمین نمی‌شود. مسدود بودن IP یا دامنه، اپراتور، مسیر شبکه و تنظیمات میزبان روی نتیجه اثر دارند.

**این پیاده‌سازی فقط TCP را پشتیبانی می‌کند.** UDP، QUIC، Mux و XUDP پیاده‌سازی نشده‌اند و صریحاً رد می‌شوند. برای بازی‌ها، تماس‌های وابسته به UDP و نیاز به VPN کامل، یک سرور استاندارد Xray با پشتیبانی لازم مناسب‌تر است. در کلاینت Mux را خاموش کنید و DNS را روی DoH/DoT یا مسیر TCP قابل‌دسترسی تنظیم کنید. قابلیت REALITY در این پروژه وجود ندارد.

## راه‌اندازی با Docker Compose و HTTPS

برای این نسخه، مسیر پیشنهادی یک سرور Linux خارج از ایران با **Docker Engine + Docker Compose** و یک دامنه است. این پیشنهاد به معنی تأیید قابل‌دسترسی بودن سرور از ایران نیست. قبل از خرید یا انتقال کامل استفاده، IP و دامنه را روی اینترنت خودتان آزمایش کنید.

1. Docker Engine و افزونه Compose را طبق [راهنمای رسمی](https://docs.docker.com/engine/install/) نصب کنید.
2. رکورد A دامنه، مثلاً `vpn.example.com`، را به IP سرور وصل کنید. اگر IPv6 درست تنظیم نشده، رکورد AAAA اضافه نکنید. پورت‌های TCP 80 و 443 باید باز و آزاد باشند.
3. پروژه را دریافت کنید و تنظیمات را بسازید:

```bash
git clone https://github.com/mahmoud2584100/Vpn.git
cd Vpn
cp .env.example .env
```

تا پیش از ادغام اصلاحات در شاخه اصلی، پس از clone این دستور را اجرا کنید:

```bash
git switch review/transport-reliability
```

در فایل `.env` مقدارهای زیر را تنظیم کنید؛ دامنه بدون `https://` و بدون مسیر باشد:

```dotenv
PUBLIC_HOST=vpn.example.com
ADMIN_PASSWORD=YOUR_LONG_RANDOM_PASSWORD
```

رمز تصادفی حداقل ۱۲ کاراکتری استفاده کنید و `.env` را در GitHub منتشر نکنید.

4. سرویس را اجرا کنید:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app caddy
```

Caddy دریافت و تمدید گواهی HTTPS را انجام می‌دهد؛ برای این کار DNS درست و پورت‌های باز لازم‌اند. منابع: [HTTPS](https://caddyserver.com/docs/automatic-https)، [Reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).

5. `https://vpn.example.com/health` باید وضعیت `ok` بدهد. سپس `https://vpn.example.com/dashboard` را باز کنید، وارد شوید، یک کانفیگ بسازید و لینک VLESS را کپی کنید. **هیچ کانفیگ پیش‌فرض خودکار ساخته نمی‌شود.**

داده‌ها در Volume `app_data` ذخیره می‌شوند. `docker compose down` آن را نگه می‌دارد؛ `docker compose down -v` داده‌ها را حذف می‌کند. تنها یک نمونه برنامه و یک worker اجرا کنید؛ سشن‌ها و شمارنده‌های زنده بین چند worker مشترک نیستند.

وجود healthcheck و `restart: unless-stopped` به معنی بازیابی خودکار تمام اختلال‌ها نیست: Docker به دلیل unhealthy شدن به‌تنهایی کانتینر را restart نمی‌کند و restart یا deploy می‌تواند اتصال‌های فعال را قطع کند.

## برنامه اتصال روی دستگاه

- اندروید: [v2rayNG — دانلود رسمی](https://github.com/2dust/v2rayNG/releases).
- ویندوز: [v2rayN — دانلود رسمی](https://github.com/2dust/v2rayN/releases).

نسخه‌ای با هسته Xray و پشتیبانی XHTTP استفاده کنید. ابتدا کانفیگ **VLESS + WebSocket** را وارد کنید. برای مقایسه، کانفیگ XHTTP با `mode=packet-up` بسازید. لینک‌های این پروژه TLS و پورت 443 دارند؛ اجرای HTTP محلی روی 8080 به‌تنهایی لینک عمومی TLS را قابل‌استفاده نمی‌کند. بررسی گواهی TLS را خاموش نکنید.

## آزمون واقعی از ایران

پس از راه‌اندازی، روی همان گوشی/کامپیوتر و اپراتور مورد استفاده:

1. بدون VPN آدرس `/health` را باز کنید. باز شدن آن تنها HTTPS را بررسی می‌کند.
2. لینک را در کلاینت وارد و اتصال را فعال کنید. IP خروجی باید با IP خروجی سرور مطابقت داشته باشد.
3. وب‌گردی، دانلود یک فایل، ارسال فایل و ویدئو را آزمایش کنید؛ هم‌زمان لاگ کلاینت و `docker compose logs -f app` را ببینید.
4. اتصال را دست‌کم ۳۰ دقیقه فعال نگه دارید و پس از چند دقیقه بیکاری دوباره درخواست بفرستید. روی Wi-Fi و دیتای موبایل جداگانه تکرار کنید. تعویض شبکه ممکن است TCP فعال را قطع کند و کلاینت باید اتصال تازه بسازد.
5. اگر WebSocket شکست خورد، XHTTP را جداگانه امتحان کنید. شکست هر دو ممکن است ناشی از مسدود شدن دامنه/IP، TLS، reverse proxy یا تنظیمات کلاینت باشد؛ نتیجه را با زمان، اپراتور و متن خطا ثبت کنید.

این آزمون فقط همان زمان و شبکه را پوشش می‌دهد و تضمین عدم قطع شدن در آینده نیست.

## اجرا بدون Compose یا روی میزبان کانتینری

Dockerfile روی پورت محیطی `PORT` (پیش‌فرض 8080 در کانتینر) اجرا می‌شود. میزبان باید HTTPS، WebSocket، پاسخ HTTP streaming بدون buffering، زمان اتصال کافی و دیسک دائمی `/data` را ارائه کند. سازگاری blitz.cloud یا Railway در این بررسی تست نشده است. توصیه نسخه قبلی درباره پایداری روی این سرویس‌ها نتیجه تست محسوب نمی‌شود.

برای اجرای مستقیم، متغیرها را در محیط فرایند تنظیم و `python main.py` اجرا کنید. `.env` برای اجرای مستقیم Python به‌صورت خودکار خوانده نمی‌شود. پنل برای استفاده عمومی نیاز به HTTPS دارد؛ کوکی ورود `Secure` است.

| متغیر | کاربرد |
|---|---|
| `PUBLIC_HOST` | دامنه عمومی؛ در صورت تنظیم، بر Host درخواست اولویت دارد |
| `ADMIN_PASSWORD` | لازم در اولین اجرا؛ در اجراهای بعد رمز ذخیره‌شده اولویت دارد |
| `DATA_DIR` | مسیر دیسک دائمی؛ پیش‌فرض `/data` |
| `PORT` | پورت داخلی؛ Compose آن را 8080 تنظیم می‌کند |
| `TCP_CONNECT_TIMEOUT` | زمان انتظار اتصال مقصد؛ پیش‌فرض ۱۵ ثانیه |
| `XHTTP_SESSION_IDLE_TIMEOUT` | مهلت سشن بدون ترافیک؛ پیش‌فرض کد ۱۲۰، Compose برابر ۳۰۰ ثانیه |
| `XHTTP_REAPER_INTERVAL` | فاصله پاکسازی سشن‌ها؛ پیش‌فرض ۱۵ ثانیه |
| `TELEGRAM_BOT_TOKEN` | توکن ربات اختیاری |
| `TELEGRAM_ADMIN_IDS` | آیدی عددی مدیران مجاز، جداشده با کاما |
| `SECRET_KEY` | برای سازگاری هش‌های قدیمی؛ در صورت نبود روی دیسک ذخیره می‌شود |

ربات و پنل فعلی کانفیگ‌های تکی را مدیریت می‌کنند. ادعای نسخه قبلی درباره گروه‌های ساب رمزدار با endpointهای این نسخه مطابقت ندارد. مسیر `/proxy/...` اکنون فقط با ورود مدیر قابل‌استفاده است. مقصدهای خصوصی، loopback و link-local در تونل VLESS به‌صورت پیش‌فرض بسته‌اند. فقط تست‌های محلی از `ALLOW_PRIVATE_DESTINATIONS=1` استفاده می‌کنند؛ آن را روی سرور عمومی فعال نکنید.

اگر نسخه قدیمی را اجرا می‌کنید، رمز عمومی `X4GKING` را از پنل تغییر دهید. هش قدیمی بعد از ورود موفق به PBKDF2 تبدیل می‌شود. نشست‌های ورود پس از restart دوباره نیاز به ورود دارند؛ رمز و کانفیگ‌ها با دیسک دائمی باقی می‌مانند. مصرف هر ۳۰ ثانیه ذخیره می‌شود؛ توقف ناگهانی ممکن است آخرین بازه مصرف را از بین ببرد.

## تست توسعه

```bash
python -m pip install -r requirements.txt
DATA_DIR=/tmp/x4g-tests ADMIN_PASSWORD=local-test-password python -m unittest -v
```

برای تست اختیاری با خود Xray، پس از نصب هسته رسمی:

```bash
XRAY_BINARY=/path/to/xray python scripts/test_xray_interop.py
```

تست‌ها روی loopback اجرا می‌شوند و تست ایران نیستند. workflow گیت‌هاب برای Python 3.11 و 3.12 اضافه شده است. Docker/Caddy و گواهی عمومی باید روی سرور واقعی جداگانه بررسی شوند.
